## 确认的 bug 及修复

### Bug 1: `check_comm_sinr` 的 `feasible` 永远是 `true`

**位置**: `tx_beamforming_robust.m` 第 337-342 行（原版）

**问题**: `feasible = true(K,1)` 初始化后，在 SINR 计算的 for 循环里从未被更新为 `sinr(k) >= gamma_bar`。无论 SINR 是多少，函数都返回"达标"。

**影响**:
- 功率分配后的"SINR 全部达标"消息不可信
- 最终诊断的"通信达标"结论不可信
- 梯度下降的可行性检查形同虚设（永远 `true`）

**修复**: `feasible` 初始化为 `false`，循环内显式 `feasible(k) = sinr(k) >= gamma_bar`。函数签名增加 `gamma_bar` 参数。所有调用点更新。

**状态**: ✅ 已修复

---

### Bug 2: 通信用户角度被 `deg2rad` 两次

**位置**: `run_tx_beamforming_demo.m` 第 67-68 行（原版）

**问题**:
```matlab
theta_rad = deg2rad(theta_comm(k));                      % 第一次: 度→弧度
a_los = generate_ura_steering(..., theta_rad, 0);        % 传入弧度值
```
而 `generate_ura_steering` 内部第 256 行又做了:
```matlab
theta = deg2rad(theta_deg);                              % 第二次: 又把"弧度"当"度"转了
```

**影响**: 四个用户方向 `[-30° -10° 20° 45°]` 实际被映射到近乎相同的 ~0° 方向（-30° → -0.5236° → -0.0091 rad ≈ -0.5°），导致 H_i 的列几乎共线。之前 ZF bad 表现（SINR 9.6 dB）部分源于此。

**修复**: 去掉调用侧的 `deg2rad`，直接传度值给 `generate_ura_steering`。

**状态**: ✅ 已修复

---

### Bug 3: 波束方向图统计丢失失真项

**位置**: `tx_beamforming_robust.m` 第 297-301 行（原版）

**问题**: 梯度优化时的目标函数是:
```
f_p = |a_T^H W_i|^2 + κ_T·a_T^H·diag{W_iW_i^H}·a_T
```
但最终保存的 `info.beam_pattern` 只算:
```
info.beam_pattern(p) = sum(abs(a_p' * W_i).^2)   % 只有信号项, 没有失真项!
```

**影响**: 报告里说"最差感知方向功率"和优化时的 `f_worst` 不是同一个量，前后不一致。

**修复**: `info.beam_pattern(p) = sig_term + dist_term`，与目标函数一致。ZF 对比波束方向图同样修正。

**状态**: ✅ 已修复

---

### Bug 4: 梯度更新没有检查通信/功率可行性

**位置**: `tx_beamforming_robust.m` 第 226-255 行（原版）

**问题**: Armijo 线搜索只检查目标函数是否提升，不检查 `W_trial` 是否满足 SINR ≥ γ̄ 或功率 ≤ P_max。这导致代码可以在后续破坏通信约束。

**影响**: 叠加 bug 1（feasible 永远全 true），梯度下降可以无限制地修改 Z，通信 SINR 可能被破坏而不被检测到。

**修复**: 在线搜索每一步增加:
```matlab
[sinr_trial, feas_trial] = check_comm_sinr(...);
P_trial = (1 + kappa_T) * trace(W_trial * W_trial');
if ~all(feas_trial) || P_trial > P_max
    mu = mu * beta_decay;  continue;
end
```
只有当同时满足 Armijo 条件和可行性约束时才接受试探点。

**状态**: ✅ 已修复

## 需要修正的理论表述（非代码 bug，但影响论文严谨性）

### 理论修正 1: "零空间不影响通信"的说法不准确

**原表述**: "N_c·Z 不会影响通信 SINR，因为 H_i^H·N_c = 0"

**修正后**: 在纯线性模型（κ_T = 0）下，H_i^H·N_c = 0 确实保证 N_c·Z 不贡献通信干扰。但当 κ_T > 0 时，发射失真项 `κ_T·h_k^H·diag{WW^H}·h_k` 与完整的 W·W^H 对角元素有关——N_c·Z 会改变对角元素，即使 H_i^H·N_c = 0。**零空间项不影响理想线性通信干扰项，但会通过发射硬件失真项影响通信 SINR。**

### 理论修正 2: 功率归一化可能破坏已满足的 SINR 约束

**原做法**: 梯度下降后的 W_i 做整体缩放 `W_i * sqrt(P_max / P_actual)`。

**问题**: 整体缩放将信号功率和干扰功率等比例缩小，但噪声项 `(1+κ_k)σ²_k` 不随 W_i 缩放。如果缩放比 < 1，通信 SINR 会下降——可能从不达标变成达标，也可能从达标变成不达标。

**建议**: 如果梯度下降中已强制满足功率约束（如本次修复所做），则不需要最终归一化。或者归一化后重新检查 SINR。

## 修复后运行结果：暴露了更深层的设计矛盾

### 新结果

| 指标 | 修复前（bug 版） | 修复后 | 说明 |
|------|:------:|:------:|------|
| 通信 SINR（功率分配后） | 9.9 dB × 4 | **10.0 dB × 4** | 刚好达标（修复前也是 9.9 但被误标达标） |
| 通信 SINR（最终） | 9.9 dB × 4 | 10.0 dB × 4 | 完全相同 |
| f_worst 提升 | +54.5% | +35.2% | 梯度下降能动但幅度受限 |
| 总功率利用率 | 100% (1.000) | **4.4% (0.044)** | Z ≈ 0，零空间几乎没更新 |
| ZF 最差感知方向 | 0.0248 | 0.1355 | 角度修复后信道更正交，ZF 表现自然改善 |
| 鲁棒最差感知方向 | 0.0446 | **0.0077** | 大幅下降！因为 Z 几乎没更新 |

### 根因分析

这是一个**鸡生蛋蛋生鸡**的矛盾：

1. 功率分配迭代把 SINR 精确调到 10.0 dB（刚好满足门限）
2. 梯度下降尝试更新 Z → N_c·Z ≠ 0 → diag{WW^H} 变化 → 失真项增大 → SINR 掉到 10 dB 以下 → 可行性约束拒绝
3. 步长被压缩到 3e-6 → Z 几乎不动 → 零空间 12 维自由度完全浪费

**本质**: `check_comm_sinr` 中的失真项 `κ_T·diag{WW^H}` 把"通信 SINR"和"感知波束"绑在了一根绳上。功率分配刚好满足 SINR 门限时，任何感知优化都会破坏通信。

### 解决方案方向

| 方案 | 思路 | 优点 | 缺点 |
|------|------|------|------|
| A: 功率余量 | 功率分配多打 1 dB（调到 11 dB） | 简单，代码只改一行 | 功率效率略降 |
| B: 放松约束 | 梯度下降允许 SINR 掉到 9.5 dB | 零空间自由度可用 | 通信可能不达标 |
| C: 联合优化 | 梯度下降时同时微调 W0 的功率分配 | 理论最优 | 复杂度大增 |
| D: 显式建模 | 在目标函数中加 SINR 惩罚项 | 连续可微 | 需要调权重 |

推荐先试 **方案 A**，改动最小且工程上合理（留 1 dB 余量是常见做法）。
