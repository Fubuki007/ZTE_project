# RIS Stage-3 AI 扩展

本目录按 [PLAN.md](PLAN.md) 分阶段实现。第一版研究思路见 [PROPOSAL_v1.md](PROPOSAL_v1.md)。全量实验配置草案见 `experiment_v1.json`。

## 当前实现范围

- `context.py`：从粗估计与已知通信模型构造独立设计输入，复制物理数组；不保存目标真值、旧 Model 对象或未来回波。
- `physics_numpy.py` / `physics_torch.py`：对全部输入频点计算照射指标和通信响应；双精度可微实现与旧 NumPy 公式对照。
- `unfolded_design.py`：默认 6 层交替波束/相位更新，每层各学习一个有界正步长，共 12 个可训练标量。初值采用现有几何量化相位与通信匹配波束。
- `repair.py`：2 bit 量化、单用户通信与总功率联合投影、原 SCA/离散坐标更新校正，失败时回退并记录原因和耗时。
- `test_design.py` / `run_checks.py`：本地数学验证与小规模反向传播冒烟。运行后保存实际测试名称、结果、版本和源码哈希。

正式训练、完整 RMSE 比较、服务器启动与作图脚本属于 G3，尚待实现。当前网络初始化或本地四步参数更新测试都不代表正式训练完成。

## 本地运行（仅数学与冒烟检查）

从仓库根目录执行：

```powershell
uv venv --python .venv-stage3/Scripts/python.exe .venv-stage3-ai
uv pip install --python .venv-stage3-ai/Scripts/python.exe -r RIS_stage3_ai/requirements.txt
.venv-stage3-ai/Scripts/python.exe -X utf8 -m RIS_stage3_ai.run_checks
```

已有环境时不要重复创建；后续直接执行检查命令。服务器单独使用 Python 3.11 AI 环境；CUDA wheel、设备与驱动信息将在部署时记录。

## 更新的具体定义

物理损失使用最弱目标照射的 soft-min（初始温度 0.03）和通信不足比例的均方罚项（初始权重 5）。这些是待训练/验证集确认的超参数，不根据测试集曲线调节。

波束梯度除以“逐子载波梯度向量二范数的均方根”，相位梯度除以“所有单元标量梯度的均方根”。分母为 `sqrt(mean_square + 1e-24)`。波束更新后投影到归一化总功率 `Ns` 的球内。初始步长为波束 0.1、相位 0.2，均通过 `0.5 * sigmoid(raw)` 限制在 (0,0.5)。相位步长按弧度计。

连续训练时相位为 `exp(j*angle)`；量化感知训练前向选择最近的 2 bit 档位，反向使用显式直通估计。直通梯度是近似，不使用有限差分声称验证其“精确性”；有限差分检查连续物理模型和连续展开网络，量化训练检查反向传播可执行与参数更新。

推理仍需计算物理目标的一阶梯度，因此 `eval()` 可用，`torch.inference_mode()` 不适用。训练还需对更新过程求导，当前实现使用 PyTorch 高阶自动微分。并未直接照搬论文全部 ADMM/DFP 算法。

## 可行性与计时

部署前逐频点检查通信门限、总功率、公共相位向量和 2 bit 档位。连续候选、量化候选、校正结果分别保存审计信息。校正首先把每个频点的通信响应旋转为实非负，再投影到通信半空间与总功率球的交集；这一投影在网络之外，以 NumPy 二分求功率乘子完成。它保证校正迭代从可行点开始，不保证相对未校正候选的照射指标增加。

校正中的 SCA 与离散坐标更新复用旧数学结构，并直接调用旧的标量对偶 SCA 子问题求解器。传统路径与旧 `Model.design()` 做完整输出回归对照。合法初值之后检查接受步骤的照射指标不下降。

如果网络候选含 NaN、维度错误或校正失败，回退必须留下原因与耗时。物理条件本身不可行时抛出失败，不返回伪造的成功配置。未来比较器要保留这类样本状态。

`network_candidate` 的候选计时包含物理数组向设备的传输、几何初始化、梯度更新和输出回传；CUDA 时同步。上下文构造时间由未来比较器另计。`repair_design` 记录校正、回退和总耗时。正式比较仍需将上下文构造、模型加载/预热约定、候选推理、校正、回退和后端估计的计时边界统一。
